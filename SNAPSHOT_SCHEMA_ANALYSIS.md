# AS_INGCO Snapshot - Schema Reference

Source file reviewed: `as_ingco.snapshot` (about 34 MB).

## Format

The file is a schema snapshot generated by SDBDiffExpress / DBDiffExpress (`SDBDiffExpress.Library`). It is not a PostgreSQL dump and should not be restored directly into CGOne.

The snapshot is highly useful as a legacy ERP schema reference. It contains SQL Server schema metadata, including table names, columns, SQL Server data types/defaults, indexes, triggers, views and stored procedure text. Evidence inside the snapshot includes `dbo`, `SQL_Latin1_General_CP1_CI_AS`, `money`, `bit`, `tinyint`, `uniqueidentifier`, and SQL Server object definitions.

Recommended CGOne mapping approach: keep the PostgreSQL model normalized. UOMID1..4 + Packing2..4 should map to `item_uoms`, not four fixed UOM columns. Legacy account IDs should map to `chart_of_accounts` relations. Legacy IDs can be retained in dedicated `legacy_*` fields for migration traceability.

### AC_Accounts

Core fields confirmed directly in the snapshot include:

- AccountID, AccountCode, ParentAccountID, AccountName
- AccountCategory, CurrencyID
- IsDebit, AccountType, Remarks
- IsDisabled, RequireCostCenter, AllowAllCostCenters
- SecurityCode, AccGroup, PlantType, CFID, ConsolGroupID
- AFlags, TargetCode, ControlBudget, BudgetGroup, OPEXGroup
- audit fields such as CreatedBy/CreateDate/LastModBy/LastMod

CGOne `chart_of_accounts` is already hierarchical and maps naturally: AccountCode -> code, AccountName -> name, ParentAccountID -> parent relation, IsDebit -> normal balance, RequireCostCenter -> require_cost_center. Legacy AccountType should be mapped into the normalized ASSET/LIABILITY/EQUITY/REVENUE/EXPENSE classes using a controlled mapping table/import rule.

## Important conclusion

This snapshot is a much better source for schema alignment than the 1.2 GB `.bak` file because the schema metadata is directly inspectable. It is suitable for designing the CGOne master data migration/import layer and for validating which legacy fields must be retained.

Do not attempt to restore this `.snapshot` into PostgreSQL. Use it as a mapping/reference source.
